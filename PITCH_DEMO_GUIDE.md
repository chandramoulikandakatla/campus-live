# CampusKart — College Pitch Demo Runbook

## Before the meeting

1. Open the public CampusKart link once on the presentation laptop and make sure it loads.
2. Open **Demo Center** from the navigation.
3. Edit the student name, ID, city, institution, hostel and parent name to match the story you want to present.
4. Keep the same browser tab/profile for the full demo. Student, Parent, Wallet, Kiosk, Operations, Rider and College experiences share browser-local demo state.
5. Start from a clean demo by selecting **Reset demo** if you have old test orders.

## Recommended 8–10 minute presentation flow

### 1. Student storefront

- Open **Student shop**.
- Explain that city, institution and hostel define the campus context.
- Search or browse essentials and add a few items.
- Open the cart, select a same-day campus delivery window and review the wallet/spending checks.
- Place a demo order under the default parent approval threshold (₹400) to show instant order placement.

### 2. Parent experience

- Open **Parent**.
- Show that the order has appeared in wallet activity and that the available demo wallet has been debited.
- Show daily and monthly spend, wallet top-up, category permissions and spending limits.
- To demonstrate approval: set **Parent approval above** to ₹100, save the policy, return to the student shop and place an order above ₹100. It will wait in the Parent Portal. Approve it here; the wallet is debited only after approval.

### 3. Student wallet and ledger

- Open **Wallet**. Show the available balance, parent-defined daily/monthly allowance, and ledger entries generated by top-ups and purchases.
- Download the demo wallet statement.

### 4. Kiosk access

- Open **Kiosk**. Enter the configured Student ID from Demo Center.
- Show account lookup and the explicitly simulated identity-check step. Explain that a production kiosk would integrate approved liveness and identity verification; this browser demo does not use a camera or biometric data.
- Open the kiosk shopping experience.

### 5. Campus fulfilment and rider handoff

- Open **Operations** and mark the order as packed.
- Open **Rider** and accept the packed order to start the demo delivery route.
- Open **Orders** in the student experience and show the six-digit demo pickup code after dispatch.
- Return to **Operations**, enter that code and confirm collection.

### 6. College experience

- Open **College**.
- Show order value, order count, fulfilment totals and product-category mix.
- Export the aggregated campus statement CSV. The report deliberately avoids student-level purchase details.

## What is simulated in this prototype

- Student sign-in and profile details are local demo identity only.
- Wallet top-ups and purchases change the browser-local demo ledger only; no payment is processed.
- Parent approvals, order states, dispatch and pickup-code validation are local simulations.
- City, profile, cart, policy, orders and wallet data are saved in this browser's local storage. They do not synchronize to another device or another visitor.
- The college dashboard provides illustrative aggregates and a downloadable CSV statement. It is not an accounting invoice or payable bill. The current source project contains 99 sample products; the original 271-SKU catalog target still needs the approved product master imported.

## Production work after the pitch

A production deployment needs authenticated student/parent accounts, verified parent-child linking, a server-side transactional wallet ledger, payment gateway verification, database-backed spending-policy enforcement, campus inventory reservations, notifications, dispatch integrations and role-based access control. Do not use the browser-only demo store as a live financial or fulfilment system.
